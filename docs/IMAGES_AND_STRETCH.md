# Изображения и режимы растяжения

Модуль: engine-graphics. Дата: 2026-08-21. Статус: реализовано, покрыто тестами (`src/test/java/com/xamlo/core/engine/graphics/components/gui/ImageStretchLayout*Test.java`).

## Назначение

Одна текстура должна корректно выглядеть на элементе любого размера и при любом соотношении сторон окна (разные мониторы, ресайз). Вся адаптация считается CPU-side как список прямоугольников «участок источника -> участок элемента»; рендерер лишь рисует получившиеся квады. Никаких GPU-sampler'ов, шейдеры не менялись.

## Координатные соглашения

| Пространство | Оси | Единицы | Где живёт |
|---|---|---|---|
| Элемент | x вправо, **y вниз**, из верхнего левого угла | логические пиксели сетки | `UIElementGeometry` |
| Источник (текстура) | x вправо, y вниз, из верхнего левого угла **целой** текстуры | пиксели файла | поля `s*` фрагмента |
| Вершина батча | нормализованный квадрат [-0.5..+0.5] вокруг центра элемента; Y инвертирован перед матрицей прохода | unit-mesh | `TexturedQuadBatch.draw` |

Матрица прохода (`UiSpaceMatrices.quadMatrix`, общий для legacy-квада и батча) сама умножает на размер элемента и применяет отрицательный масштаб по Y — поэтому вершины батча отдаются уже нормированными против размера элемента, а не в абсолютных координатах окна.

## API

Свойства доступны у любого виджета через базовый уровень (`Widget`) и зеркалятся в `ImageView`:

```java
widget.setBackgroundImage(texture);            // AbstractTexture
widget.setBackgroundStretchMode(EnumImageStretch.COVER); // null трактуется как FILL
widget.setNinePatchInsets(l, t, r, b);         // борды только для NINEPATCH
widget.setRegion(uPx, vPx, wPx, hPx);         // подрегион источника (<=0 = «до края»)
// ImageView: setImage / setStretchMode / getStretchMode — те же состояния
```

Рендерер читает эти свойства с самого виджета (`UIElementRenderer`), так что режим работает без обёртки `ImageView`.

## Режимы (`EnumImageStretch`)

| Режим | Поведение | Формула масштаба |
|---|---|---|
| `FILL` (по умолчанию) | Растянуть целиком, пропорции могут исказиться | независимые по осям |
| `FIT` | Вписать целиком, центрировать; пустоты при разном аспекте | min(dstW/srcW, dstH/srcH) |
| `CENTER` | Без масштабирования, по центру; избыток обрезается границами элемента | 1.0 |
| `COVER` | Заполнить всё, сохранить пропорции; переполнение обрезается по якорю (`setCropAnchor`, дефолт — симметричный центральный кроп). Классика для фонов под любой экран | max(dstW/srcW, dstH/srcH) + кроп от края, противоположного якорю |
| `NINEPATCH` | Углы бордов не масштабируются, кромки тянутся по одной оси, центр — по обеим | см. ниже |

Геометрия всех режимов — в чистом классе `ImageStretchLayout` (без OpenGL): диспетчер `layout(mode[, region], srcW, srcH, dstW, dstH, insets)` выдаёт список `StretchPiece(sx,sy,sw,sh,dx,dy,dw,dh)`. Математические различия FIT/CENTER/COVER:

- **FIT** никогда не обрезает изображение (может оставлять поля);
- **COVER** никогда не оставляет полей (обрезает изображение);
- **CENTER** ни то ни другое — рисует в натуральном размере и просто уходит за границы при необходимости.

### Nine-patch

Борды задаются пикселями исходного изображения (`NinePatchInsets`). Раскладка 3×3: угловые фрагменты сохраняют нативный размер, средние стороны тянутся вдоль своей оси, центр поглощает остаток. Если элемент меньше суммы «углы + минимальная середина», вся раскладка равномерно сжимается до размеров элемента (единственный случай масштабирования углов). Борды больше половины стороны ужимаются пропорционально; нулевые фрагменты не выдаются.

## Подрегион источника (`setRegion`)

Кроп применяется **первым**: до маппинга режима растяжения и до интерпретации борд nine-patch (борды считаются уже внутри вырезанного куска). Смещения и размеры клампятся внутрь текстуры; `width<=0` / `height<=0` означают «до края» по соответствующей оси. Координаты `s*` всех выданных фрагментов включают смещение от угла всей текстуры, поэтому UV нормализуются против полного размера без дополнительных правок. Комбинации: `COVER + region` = заполнить область центральным куском заданной под-области.

 ## Якорь обрезания/выравнивания (`setCropAnchor`)

 Параметр — точка единичного квадрата [0..1]² (`StretchAnchor`, дефолт центр `(0.5, 0.5)`), семантика совпадает с процентным CSS background-position/object-position: доля свободного места или переполнения, остающаяся **слева**/**сверху**, равна x/y якоря. Действует на три режима со смещением:
 
 - **COVER/CENTER** при переполнении: обрезается часть, противоположная якорю — `(0,0)` держит левый верхний угол изображения, `(1,1)` — правый нижний, середины кромок дают крайние позиции;
 - **FIT**: letterbox-поля распределяются по тому же правилу (прижато к краю вместо центра).
 
 FILL и NINEPATCH якорь игнорируют; значения вне [0..1] обрезаются до границ, NaN трактуется как центр. Математика — перегрузки `cover/fit/centerCrop/computeFitRect` c якорём в `ImageStretchLayout`; диспетчеры `layout(...)` принимают его последними двумя аргументами (старые сигнатуры делегируют на центр = историческое поведение побайтово).

## Два рендерных пути в `UIElementRenderer`

1. **Legacy unit-mesh** — цветные квады, чистый FILL (проверка `isPlainFill`) И одиночные нетривиальные режимы растяжения (FILL-регион/FIT/CENTER/COVER без nine-patch): в последнем случае тот же unit-mesh рисуется с аффинным преобразованием UV и позиции через юниформы `useTexAffine/uvMul/uvAdd/posScale/posOffset` общего GUI-шейдера — на этом окружении CPU-side батч ниже детерминированно не отрисовывается, поэтому единственный фрагмент обходит его полностью. Статическая меш-геометрия, один `glDrawElements`.
2. **Динамический батч** (`TexturedQuadBatch`) — мультифрагментные раскладки (nine-patch) и неполный регион при FILL: VAO с двумя атрибутами (pos vec3 @ stride 20B offset 0, uv vec2 @ offset 12), вершины пересобираются каждый кадр из списка фрагментов, индексы переиспользуются. Матрица общая у прохода элемента (не своя ортогональная). Известное ограничение этого пути на текущем окружении см. в п.1; nine-patch фактических потребителей пока нет.

> **Важно (урок отладки):** глобальный бэкфес-калллинг включён в `RenderEngine.init()` (CCW + BACK). Из-за отрицательного масштаба Y в матрице прохода «правильная» закрутка треугольников батча — противочасовая `(0)(3)(1)|(1)(3)(2)`; при обратной ориентации **все квады молча отсекаются как задние грани**, и элемент просто не виден ни при каких координатах. Если новый текстурированный путь «ничего не рисует», первым делом проверяйте winding, а уже потом координаты.

## Поведение при ресайзе

Раскладка вычисляется на каждом вызове draw'а актуальной геометрией элемента, поэтому изменение размера окна/виджета автоматически пересчитывает режимы (включая COVER) без какого-либо кэша — см. коммиты по propagации resize (E9) в корне репозитория.
